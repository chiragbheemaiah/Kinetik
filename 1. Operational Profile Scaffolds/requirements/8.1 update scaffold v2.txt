2. JSON Design Requirements
2.1. Common schema for each subsection
Every subsection object in the JSON should, at minimum, support:
* id: string (e.g., "1.6")
* title: string
* description: high-level intent (for humans)
* llm_prompt: concrete instructions to the LLM
* output_type: enum, one of:
o "text_narrative"
o "table"
o "org_chart"
o "leadership_profiles"
o "transcript_analysis"
* constraints (object), optional keys:
o word_count_min / word_count_max (for narratives)
o max_items (e.g., top 10, top 20)
o levels_of_hierarchy (for org charts)
* table_definition (for output_type = "table"):
o columns: array of { "name": string, "description": string }
* org_chart_definition (for output_type = "org_chart"):
o levels: integer (e.g., 3 levels deep including top leader)
o include_names: boolean (always true here)
o include_titles: boolean
* leadership_profile_schema (for output_type = "leadership_profiles"):
o List of fields (see ?4.3 & ?7.1)
* source_guidance: textual guidance for the LLM regarding typical sources (10-K, earnings call transcripts, analyst reports, etc.).
Developer should ensure this schema is reusable so new sections or changes are easy to add.
